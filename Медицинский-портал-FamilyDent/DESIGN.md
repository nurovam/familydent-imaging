# FamilyDent · медицинский портал

Подробные извлечённые значения: [brand-spec.md](brand-spec.md). Фактическая система опубликованного сайта имеет приоритет над прежними предпочтениями из памяти.

## Архитектура
- index.html — стартовая навигация по рабочим пространствам.
- login.html — email, выбор рабочего пространства, состояние кода, ошибка и возврат.
- doctor.html — назначенные пациенты, поиск, статусы, фильтр типов, история пациента.
- study.html — схема просмотра серии, масштаб, контраст, инверсия, поворот, измерение в px, срезы.
- upload.html — реальные локальные файлы, проверка расширения/размера, сведения о пациенте, назначение врача, проверка, сохранение карточки.
- admin.html — сотрудники, роли, ограничение доступа, клиники, временные ссылки, журнал событий.
- patient.html — исследование, просмотр, варианты скачивания, истечение срока ссылки.

## I-Lang
Палитра: white / paper-2 / graphite + мягкое золото; зелёный только для семантических статусов. Типографика: Roboto Serif 28–38 px для заголовков, Golos Text 14 px для интерфейса и 10–12 px для метаданных. Плотность: таблица в центре, узкая контекстная колонка справа. Радиусы: 10–18 px для контейнеров, pill для действий. Границы: 1 px. Шаг: 8 px. Акцент: выбранная навигация и основное действие. Анимация: только короткие переходы; reduced-motion поддерживается.

## Адаптация
1920–1280: боковая навигация, таблицы и контекстная колонка. До 1200: контекстные блоки ниже таблицы. До 900: раскрываемая навигация, один основной столбец. До 600: таблицы превращаются в записи пациента, поля формы выстраиваются вертикально; просмотрщик сохраняет панель инструментов и серии. Минимальная целевая ширина 360 px. Доступны стили focus-visible, семантические подписи, aria-selected и aria-expanded.

## Проверяемые взаимодействия
1. Вход: email валидируется браузером; код 246810 открывает выбранное пространство, иной код вызывает ошибку. Это локальная модель UX, не аутентификация.
2. Врач: поиск по имени/ID, фильтр модальности, вкладки статуса, история пациента, переход к нужной записи.
3. Просмотр: выбрать серию, менять срезы аксиальной серии, масштаб, контраст, инверсию, поворот; инструмент расстояния показывает пиксели схемы. Нет медицинского DICOM-декодирования или калибровки в мм.
4. Загрузка: выбрать непустой .dcm/.zip до 2 ГБ, заполнить пациента и дату, назначить активного врача, проверить и сохранить локальные метаданные. Файлы не передаются на сервер.
5. Управление: приглашения, смена роли, ограничение доступа, новая клиника, поиск в журнале, создание/отзыв ссылки.
6. Пациент: созданная локальная ссылка проверяет token и срок в текущем браузере; отзыв/истечение ведут к состоянию недоступности. Самостоятельный patient.html — открытая вымышленная исходная карточка.

## Интеграционные границы
Серверная авторизация, разграничение ролей, одноразовые email-коды, отправка писем, хранение DICOM, реальный Romexis Viewer, защищённая выдача/отзыв ссылок и неизменяемый аудит должны быть реализованы сервером. localStorage хранит только вымышленные записи для взаимодействий; это не механизм безопасности. Контакты example.test — намеренно тестовые адреса. В интерфейсе скачивания нет фиктивных архивов. Данные вымышлены; схема исследования создана программно.

## Контроль качества
P0: русский интерфейс; отдельный файл для каждого экрана; валидный JS; все внутренние ссылки ведут на существующие файлы; нет фиктивных DICOM-архивов; нет утверждений об отправленных письмах; нет диагностического использования схемы.
P1: мобильные карточки вместо сжатой таблицы; не менее 44 px для основных действий; доступность клавиатурой; отмена модальных окон и возврат по шагам; пустые и ошибочные состояния.
P2: единые токены и оригинальный контурный SVG-логотип из референса; сдержанная палитра; уникальные data-od-id.
